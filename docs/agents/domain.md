# Domain Docs

This is a single-context repository.

Before exploring or changing an area, read the root `CONTEXT.md` when it exists and the relevant decisions in `docs/adr/`. If either does not exist yet, proceed and let domain modeling create it when a term or decision needs to be recorded.

Use the glossary vocabulary from `CONTEXT.md` in issue titles, specifications, code-facing explanations, and tests. If the needed concept is missing or overloaded, resolve it through domain modeling before introducing a new synonym.

If a proposed change conflicts with an ADR, surface the conflict explicitly before changing the implementation or the decision record.
